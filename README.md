# TraceForge

> **Forge software that endures.**

TraceForge is an AI-Assisted Software Development Methodology accompanied by a custom GPT implementation.

Its purpose is to help developers design maintainable systems, preserve architectural integrity, plan incremental releases, and make engineering decisions that remain valuable years into a project's lifecycle.

Rather than optimizing for the fastest solution, TraceForge optimizes for software that remains understandable, reliable, and maintainable for years to come.

---

# Why TraceForge Exists

Modern AI coding assistants excel at generating code.

TraceForge exists to help answer a different question:

> **"Is this the right solution for the project?"**

It emphasizes architecture before implementation, long-term thinking over short-term convenience, and thoughtful engineering over trend-driven complexity.

TraceForge collaborates as an experienced engineering partner—reviewing designs, challenging assumptions when appropriate, and helping projects evolve one milestone at a time.

# Core Principles

TraceForge is built upon several fundamental principles:

- Architecture before implementation
- Think in versions, not isolated tasks
- Preserve existing architecture whenever practical
- Prefer incremental improvements over disruptive rewrites
- Favor simplicity over unnecessary complexity
- Treat documentation as part of the architecture
- Build software that future developers will understand and enjoy maintaining

# Getting the Best Results

TraceForge provides the best recommendations when it understands the project it is working with.

For existing projects, consider sharing:

- the project as a ZIP archive
- the repository structure
- README documentation
- ROADMAP
- AGENTS
- architecture documentation
- current milestone
- relevant source files

The more architectural context TraceForge has, the better it can preserve existing design decisions and recommend changes that integrate naturally into the project.

For new projects, begin by discussing:

- the project's purpose
- intended users
- constraints
- long-term goals

TraceForge will help establish the roadmap, architecture, documentation, and implementation strategy before significant development begins.

# Typical Collaboration Workflow

## Existing Projects

1. Share the project or repository.
2. Explain the current milestone.
3. Review the existing architecture.
4. Discuss proposed changes.
5. Implement incrementally.
6. Review the results.
7. Update documentation.

## New Projects

1. Define the vision.
2. Break work into milestones.
3. Design the architecture.
4. Prepare project documentation.
5. Implement incrementally.
6. Review.
7. Release.
8. Repeat.

---

# What TraceForge Won't Do

TraceForge intentionally avoids recommendations that increase long-term maintenance costs without sufficient benefit.

It generally will not recommend:

- rewriting stable code without clear justification
- introducing unnecessary architectural complexity
- skipping architectural planning for major features
- adopting technologies simply because they are popular
- sacrificing maintainability for short-term convenience

When appropriate, TraceForge will recommend preserving an existing design rather than replacing it.
